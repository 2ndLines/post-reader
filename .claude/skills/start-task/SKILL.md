# start-task：开始一张任务卡

参数：任务卡编号（如 `P0-REPO-05`）。依据：docs/archs/ai-dev-playbook.md §3（核心工作循环）、§4.1（会话纪律）、§5（任务拆分）、§11（人工检查点）。

## 步骤
1. 读 `docs/tasks/<编号>.md`。没有验收标准时，先补写验收标准并停下请负责人确认（§3.1 第 1 步）。
2. 读任务卡「依据」列出的 PRD 与架构章节，只读这些章节；再读相关的 `apps/*/AGENTS.md`，以及 `docs/progress/STATUS.md` 中与本卡相关的阻塞项。
3. 检查依赖的任务卡是否已完成（`docs/tasks/README.md` 的状态列）；未完成时说明本卡要叠在哪个分支上。
4. 填写任务卡的「上下文摘要」：5–10 行，写我理解的需求、涉及的模块、已有实现、约束。读过的结论写进去，后续会话不必重读。
5. 填写「计划」：要新增或修改的文件、数据与接口变更、测试计划（每条验收标准对应哪个测试或证据）、文档同步点（§4.4）、是否引入新依赖（需要时走 `add-dependency`）。
6. 填写「风险与问题」：文档冲突（按 §0.1 优先级裁决，并写明取舍）、未决事项（按「未决前的默认」执行，见 ADR 0004）、需要负责人决定的问题（给出默认做法）。
7. 判断是否触发人工检查点（§11）或停止条件（§3.2）：触发则停下，把计划交负责人确认；未触发且负责人已授权自行推进时继续。
8. 从 `main`（或依赖卡的分支）拉出 `feat/<编号小写>` 分支，例如 `feat/p0-repo-05`。

## 完成时必须产出
- 任务卡四节中的前三节已填写，并写明日期与状态
- 已确定的分支名与 base 分支
- 需要负责人回答的问题清单（可以为空），每个问题附默认做法
