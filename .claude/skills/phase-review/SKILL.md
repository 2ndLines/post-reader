# phase-review：阶段出口评审

参数：阶段编号（`P0`–`P12`）。依据：docs/archs/ai-dev-playbook.md §6（各阶段的交付物、出口条件与人工检查点）。

## 步骤
1. 从 playbook §6 找到该阶段的小节，列出全部交付物、出口条件与人工检查点。
2. 对每个交付物：找到对应的任务卡与 PR，确认已合并（`gh pr view <编号> --json state,mergedAt`）。只合并了一部分或还没合并的，列为未完成。
3. 对每条出口条件：给出可核实的证据（命令输出、CI 运行链接、台架报告）。不能由助手核实的项目（真机、云账号、GitHub 设置）标为「待负责人确认」，并写明怎么确认。
4. 汇总各任务卡交接记录中「未完成」或「待负责人」的事项。
5. 列出本阶段新增的 ADR 及其状态，以及本阶段对 PRD 和架构文档的版本变更。

## 输出（评审报告，写入 docs/progress/ 或 PR 描述，由负责人决定）
- 出口条件逐条：满足 / 未满足 / 待负责人确认，附证据
- 遗留事项与建议的处理方式（带入下一阶段 / 本阶段补完）
- 是否建议进入下一阶段。由负责人在评审中确认，助手不自行宣布阶段完成
