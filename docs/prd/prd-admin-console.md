## 1. 文档边界、版本履历与符号规范

### 1.1 文档范围与职责
* **范围内**：管理后台的定位、用户角色、使用场景、功能需求、权限规则、非功能需求、安全与合规要求、上线验收门禁。
* **范围外**：
  1. 后台的技术实现（归口《03 管理后台架构设计》《02 后端架构设计》）。
  2. 提示词、站点提取规则、音色表、档位参数等共享配置的**内容编辑**。这些配置在代码仓库中修改并经测试台架门禁，后台只负责发布、灰度与回滚（见 5.8）。
  3. 查看任何帖子正文、评论、译文、帖子 URL、用户邮箱明文。后台**不提供**此类能力，客服问题只能通过账户状态、配额流水与任务元数据处理。用户为复现问题自愿提供的帖子链接只在外部工单系统中流转，不进入后台。
  4. 跨区域汇总视图。国内与海外各部署一套后台，各自只操作本区数据（主 PRD 9.3）。
  5. 向用户发送消息、推送或邮件营销（投诉与个人数据请求的处理结果只更新为 App 内可见的状态，不另发消息）；订阅退款（由 App Store 处理）；首页「推荐」内容的编辑运营（主 PRD 未定义推荐来源，列为待确认项 Q7）。
  6. 运行时开关之外的任何线上配置修改（见 5.15 与原则 3）。
  7. 完整的工单系统与值班排班。后台只负责告警的确认与结论、事件记录与补偿；客诉往来在外部邮件或工单系统中进行，后台以外部工单号关联（ADM-AUD-04）。

## 2. 产品定位与目标

### 2.1 定位
管理后台是供内部人员使用的运营工具，用于：查看服务健康与业务指标、处理账户与配额问题、跟踪注销与数据导出请求、发布共享配置、在故障时通过告警、事件记录与运行时开关完成发现、止血、补偿与复盘，下架违规或侵权的公共缓存内容，维护预置样帖、监控站点适配与风控、处理国内投诉举报并满足合规查询与审计要求。

### 2.2 设计原则
1. **数据不出区**：国内后台只连国内区数据，海外后台只连海外区数据，任何页面都不汇总两区数据。
2. **默认看不到内容**：后台没有查看帖子内容与邮箱明文的入口；即使数据库中存在加密字段，后台账号也没有读取权限。
3. **配置不在线编辑**：避免两区配置被各自修改而漂移，也保证每个上线的配置版本都经过测试台架门禁。
4. **最小权限、可追溯**：日常用低权限角色工作；所有写操作都有审计记录，敏感操作要求重新验证并填写原因。
5. **能止血，不绕过门禁**：紧急情况只能通过运行时开关在已通过门禁的路径之间切换（如切到备用厂商、暂停受理），不能在后台改写配置内容。

### 2.3 目标
| 目标 | 衡量方式 |
| :--- | :--- |
| 客服问题可闭环 | 「额度不对」「订阅未生效」「注销进度」三类问题能在后台内查清并处理，不需要直接查询生产数据库 |
| 配置发布可控 | 100% 的线上配置版本来自后台发布记录，且都有对应的测试台架门禁报告 |
| 合规可查 | 国内区能按时间与类别出具机审拦截统计与后台操作审计 |
| 误操作可防 | 危险操作均有二次确认、原因与重新验证；错误区域操作风险通过区域标识降低 |
| 故障可止血 | 厂商故障、注入事件、站点大面积失败时，运行时开关在 $T_{\text{flag\_apply}}$ 内全区生效 |
| 个人数据请求按期完成 | 注销与导出请求 100% 在期限内完成，期限内未完成的有告警 |
| 投诉按时反馈（国内） | 投诉举报 100% 在 $T_{\text{complaint}}$ 内给出处理结果 |
| 告警有人管 | 100% 的告警在 $T_{\text{ack}}$ 内被确认，且关闭时有结论 |
| 故障可复盘 | 每次使用运行时开关、紧急回滚或批量补偿，都能在一条事件记录中看到起因、动作与影响 |
| 定价有数据 | 每周可导出各档位用量与成本分布，作为《商业化精算与配额配置表》的输入 |

## 3. 用户角色

初期为一人公司，同一个人持有多个角色，通过「角色切换」在任意时刻只启用一个角色（见 5.1）。

| 角色 | 典型使用者 | 职责 |
| :--- | :--- | :--- |
| `viewer` | 所有后台账号 | 查看仪表盘、站点适配监控、只读配置 |
| `support` | 客服 | 查询账户状态、配额流水、订阅事件、注销与数据导出进度；吊销用户会话 |
| `ops` | 运营 | 配额补偿（含发起批量补偿）、预置样帖维护、风控处理、注销与导出工单手动重试、设置运行时开关、创建与关闭事件记录、海外区公共缓存下架 |
| `publisher` | 发布负责人 | 配置版本发布、灰度、回滚；设置运行时开关 |
| `compliance` | 合规负责人（仅国内区） | 查看机审拦截统计、备案公示与合成标识信息、处理投诉举报、国内区公共缓存下架、导出审计 |
| `owner` | 产品负责人 | 后台账号与角色管理、查看后台操作审计、系统设置（区域状态、告警渠道与阈值）、发布含档位参数的配置版本、确认批量补偿 |

**职责分离规则**：`compliance` 不继承其他角色；`owner` 也不能查看机审拦截记录，除非同时被授予 `compliance`。

## 4. 使用场景

| 编号 | 场景 | 角色 | 流程概要 | 涉及模块 |
| :--- | :--- | :--- | :--- | :--- |
| S1 | 用户反馈「本月额度突然没了」 | support → ops | 按用户提供的支持码查账户 → 查看配额流水与对应任务元数据 → 确认属系统问题 → 切换 ops 角色补偿并填写原因 | 5.3、5.5 |
| S2 | 用户反馈「已订阅但仍是免费档」 | support | 查账户档位 → 查订阅事件与对账结果 → 必要时触发单用户对账 | 5.3、5.6 |
| S3 | 海外用户申请注销已 21 小时未完成 | support → ops | 注销工单列表按倒计时排序 → 查看卡在哪一步 → 手动重试 | 5.7 |
| S4 | 发布新的提示词版本 | publisher | 选择候选版本 → 核对两区门禁报告与差异 → 以 5% 灰度发布 → 观察指标 → 逐级放量或回滚 | 5.8、5.2 |
| S5 | 某站点改版导致抓取失败率上升 | viewer → 开发 | 站点适配监控发现失败率异常 → 开发在仓库更新规则 → 走 S4 流程发布客户端配置包 | 5.9、5.8 |
| S6 | 更换首页预置样帖 | ops | 上传新样帖音频与脚本 → 国内区样帖须经机审 → 设置排序 → 上线 | 5.10 |
| S7 | 监管或内部检查要求出具拦截统计与操作记录 | compliance | 按时间与类别查看机审拦截统计 → 导出 | 5.11、5.13 |
| S8 | 发现某账号用量异常、疑似盗刷 | ops | 风控列表定位账号 → 查看设备证明失败与频控命中 → 吊销会话、标记风险 | 5.12、5.4 |

| S11 | 用户在 App 内投诉某段播报内容违规（国内） | compliance | 投诉队列按剩余时限排序 → 按任务 ID 查看机审记录与任务元数据 → 判定并记录处理结果 → 用户在 App 内看到处理状态 | 5.11 |
| S12 | 海外用户申请导出个人数据 | support | 数据请求列表查看进度 → 生成失败时切换 ops 重试 → 完成后用户在 App 内下载 | 5.16 |
| S13 | 某站点完整性校验失败率突增 | viewer → 开发 | 仪表盘完整性失败率告警 → 按站点规则与任务 ID 定位 → 服务端已确认的切片已自动退还 → 开发排查并修复 | 5.2、5.5、5.9 |
| S14 | 国内区建成并开始预发 | owner | 把国内区状态从「未启用」改为「预发」→ 此后候选版本须同时通过国内区门禁才能发布 | 5.8、5.14 |

## 5. 功能需求

需求编号格式 `ADM-<模块>-<序号>`。「必须」为 MVP 范围，「应」为 MVP 后迭代。

### 5.1 登录、会话与角色切换（AUTH）
| 编号 | 需求 | 级别 |
| :--- | :--- | :--- |
| ADM-AUTH-01 | 访问后台须先通过区域零信任网关，再以 Passkey 登录；不提供密码登录。 | 必须 |
| ADM-AUTH-02 | 后台账号只能通过 `owner` 发出的邀请链接注册，链接有效期 $T_{\text{invite}}$，一次性使用。 | 必须 |
| ADM-AUTH-03 | 会话无操作 $T_{\text{admin\_idle}}$ 后过期，登录后最长 $T_{\text{admin\_abs}}$ 必须重新登录。 | 必须 |
| ADM-AUTH-04 | 顶栏提供角色切换，任一时刻只启用一个角色；切换到 `ops`、`publisher`、`compliance`、`owner` 需重新验证 Passkey。 | 必须 |
| ADM-AUTH-05 | 敏感操作（补偿、发布、回滚、吊销用户全部会话、修改后台账号角色）须在 $T_{\text{reauth}}$ 内完成过一次重新验证，否则弹出验证。 | 必须 |
| ADM-AUTH-06 | 顶栏始终显示当前区域（国内 / 海外）标识与区域主色色条，不可隐藏。 | 必须 |

| ADM-DASH-02 | 指标卡支持选择时间范围（1 h / 24 h / 7 d / 28 d），点击进入趋势图。 | 必须 |
| ADM-DASH-03 | 展示厂商维度的首包延迟、错误率与备用切换次数。 | 必须 |

| ADM-ADMU-01 | `owner` 可邀请账号、分配或收回角色、停用账号；不可删除账号（保留审计关联）。 | 必须 |
| ADM-ADMU-02 | 系统至少保留一个可用的 `owner`；最后一个 `owner` 不可被停用或降权。 | 必须 |
| ADM-ADMU-03 | 每个后台账号可注册多个 Passkey，可自助移除自己的 Passkey（至少保留一个）。 | 必须 |

### 5.15 运行时开关（FLAG）
运行时开关是紧急止血手段：只在**已经通过门禁**的路径之间切换，不改写任何配置内容（原则 5，评审 F08）。

| 编号 | 需求 | 级别 |
| :--- | :--- | :--- |
| ADM-FLAG-01 | 只提供下表白名单中的开关，取值为封闭枚举；后台不能新增开关或输入自由取值。白名单的增减走代码仓库与正常发布。 | 必须 |
| ADM-FLAG-02 | `ops`、`publisher`、`owner` 可设置开关：须重新验证、选择原因类别并填写说明、选择有效期（≤ $T_{\text{flag\_max}}$）。 | 必须 |
| ADM-FLAG-03 | 开关在 $T_{\text{flag\_apply}}$ 内对本区全部服务端实例生效；涉及客户端的开关在客户端下次启动或回到前台时生效。页面显示每个实例的生效确认。 | 必须 |
| ADM-FLAG-04 | 到期自动恢复为配置中的默认值；到期前可续期，每次续期记入审计；可随时手动关闭。 | 必须 |
| ADM-FLAG-05 | 开关优先于配置中的同名默认值。灰度中的配置版本若修改了同一开关的默认值，发布页提示「被运行时开关覆盖」。 | 必须 |
| ADM-FLAG-06 | 开关列表展示当前状态、设置人、原因、剩余有效期与历史记录。 | 必须 |

| 开关 | 取值 | 效果 | 用户侧表现（主 PRD 依据） |
| :--- | :--- | :--- | :--- |
| 暂停受理新任务 | 开 / 关 | 服务端拒绝新建云端合成任务；进行中的任务继续 | 提示服务维护中；可复听已缓存内容与本机朗读（10.2） |
| 强制使用备用 TTS | 按语种：开 / 关 | 不再尝试主厂商，直接走备用厂商 | 无感（10.2） |
| 强制使用备用 LLM | 开 / 关 | 选拔、串场、翻译改走备用厂商 | 无感 |
| 关闭跨语种分支 | 开 / 关 | 不再发起分支 B | 外语帖按端侧兜底处理：本机离线翻译或提示并跳过（10.2） |
| 停用站点规则 | 按站点规则 ID：开 / 关 | 客户端不再用该规则采集 | 该站点链接提示「暂不支持，可查看原文」 |
| 暂停公共缓存 | 开 / 关 | 公共缓存停止读写，全部按私有路径合成 | 无感；成本上升（9.1.3） |

### 5.17 告警中心（ALERT）
各模块的告警（注销与导出临期、完整性失败率、订阅事件处理失败、投诉临期、站点成功率、灰度指标越界、两区版本漂移、运行时开关即将到期、风险复核到期）统一进入告警中心，保证每条告警都有人确认、有结论。

| 编号 | 需求 | 级别 |
| :--- | :--- | :--- |
| ADM-ALERT-01 | 告警分「紧急」「一般」两级，按来源模块路由到负责角色；同时推送到本区配置的值班渠道（邮件或即时通讯 Webhook，见 5.20）。推送内容只含告警类型、对象 ID 与后台链接，不含用户信息。 | 必须 |
| ADM-ALERT-02 | 负责角色须在 $T_{\text{ack}}$ 内确认；超时未确认自动升级给 `owner` 并再次推送。 | 必须 |
| ADM-ALERT-03 | 关闭告警须选择结论（已处理 / 误报 / 转为事件 / 已知问题）并填写说明；「转为事件」时创建事件记录并关联（5.18）。 | 必须 |
| ADM-ALERT-04 | 同一来源与对象的重复告警合并计数，不重复推送；告警列表可按状态、级别、来源筛选。 | 必须 |
| ADM-ALERT-05 | 每日生成一次未关闭告警摘要推送到值班渠道。 | 应 |

### 5.19 公共缓存治理（CACHE）
公共共享缓存（主 PRD 9.1.3）会把一次合成的音频提供给多个用户；违规或侵权内容需要能够下架并防止再次进入缓存。

| 编号 | 需求 | 级别 |
| :--- | :--- | :--- |
| ADM-CACHE-01 | 按任务 ID 下架该任务产生的全部公共缓存切片，并把对应的内容键加入禁止缓存名单；名单只保存内容键（摘要），不保存任何文本。海外区由 `ops`、国内区由 `compliance` 执行，`owner` 两区均可；须重新验证、填写原因与来源（投诉结论 / 权利人通知 / 内部发现）和外部工单号。 | 必须 |
| ADM-CACHE-02 | 下架后 $T_{\text{purge}}$ 内该内容在全部用户侧不可再命中公共缓存；之后同一内容只能按私有路径合成，不再写入公共缓存。 | 必须 |
| ADM-CACHE-03 | 名单列表展示下架时间、执行人、原因与来源；移除名单条目须重新验证并填写原因。 | 必须 |
| ADM-CACHE-04 | 只读展示公共缓存的容量、命中率与按站点的分布。 | 必须 |

## 8. 安全与合规

1. 后台只能经零信任网关访问，不对公网直接开放。
2. 后台账号的数据库权限无法读取任何加密内容字段、用户数据密钥与正文字段（技术约束见架构设计 03 §7.3）。
3. 页面与接口响应中不得出现：邮箱明文、帖子正文、评论、译文、帖子 URL、第三方站点 Cookie。
4. 页面不加载任何第三方脚本、字体或统计服务。
5. 后台错误上报只发送到本区实例，并去除 URL 参数与表单值。
6. 国内区的合规页面仅 `compliance` 角色可见；海外区不部署合规模块。
7. 支持码由用户 ID 不可逆派生，不能反推用户 ID；支持码只用于查询，不作为任何身份凭证。
8. 投诉中用户自填的文字按个人信息处理：只对 `compliance` 可见，不进入日志与错误上报，随投诉记录的保留期删除。
9. 后台人员无法查看或下载用户的数据导出文件。

## 9. 上线前验收门禁

1. **权限门禁**：全部接口 × 全部角色的自动化矩阵测试，与第 6 节一致率 = 100%；未登记权限的接口数 = 0。
2. **内容零暴露门禁**：对全部后台接口响应与页面快照做自动化扫描，邮箱明文、正文、URL、Cookie 出现次数 = 0。
3. **审计完整门禁**：全部写接口调用后均产生审计记录，覆盖率 = 100%；审计表的更新、删除操作被数据库拒绝。
4. **配置发布门禁**：门禁未通过的候选版本发布成功次数 = 0；灰度同时进行的版本数 ≤ 1；回滚后 5 分钟内服务端生效版本正确率 = 100%。
5. **补偿限额门禁**：超过 $C_{\text{comp\_max}}$ 或 $C_{\text{comp\_daily}}$ 的补偿成功次数 = 0；缺少原因或未重新验证的敏感操作成功次数 = 0。
6. **注销可见门禁**：测试注销工单的每一步状态在后台可见，倒计时与实际期限误差 ≤ 1 min；超时预警在剩余 $T_{\text{del\_warn}}$ 时触发。
7. **区域隔离门禁**：国内后台访问海外区数据的成功次数 = 0，反之亦然；顶栏区域标识与实际连接区域一致率 = 100%。
8. **运行时开关门禁**：白名单外的开关设置成功次数 = 0；设置后 $T_{\text{flag\_apply}}$ 内全部实例生效率 = 100%；到期自动恢复率 = 100%；每次设置、续期、关闭均有审计。
9. **兼容与门禁联动**：不兼容目标区域服务端版本的配置包发布成功次数 = 0；G9 未通过的客户端包发布成功次数 = 0；非 `owner` 发布含档位参数变更的版本成功次数 = 0。
10. **个人数据请求门禁**：测试导出请求在期限内完成率 = 100%；导出文件不含帖子内容；后台人员访问导出文件的成功次数 = 0；注销后后台审计中该用户的明文标识出现次数 = 0。
11. **投诉处理门禁（国内）**：测试投诉从提交到在后台出现 ≤ 1 min；处理结论提交后 App 内状态更新 ≤ 1 min；超时预警按时触发。
12. **告警闭环门禁**：注入每一类告警源，告警中心出现率 = 100%，值班渠道收到率 = 100%；超过 $T_{\text{ack}}$ 未确认的升级率 = 100%；无结论关闭的成功次数 = 0。
13. **缓存下架门禁**：下架后 $T_{\text{purge}}$ 内对该内容的公共缓存命中次数 = 0；名单中的内容再次写入公共缓存的次数 = 0。
14. **发布控制门禁**：未满 $T_{\text{canary\_min}}$ 且非 `owner` 跳过时放量成功次数 = 0；门禁证明验签失败或版本不匹配时发布成功次数 = 0。
15. **账号恢复门禁**：恢复码登录只能注册 Passkey、其他操作成功次数 = 0；恢复后旧恢复码再次使用成功次数 = 0；全部后台账号收到告警。
16. **事件完整门禁**：事件期间的开关、回滚、批量补偿自动关联率 = 100%；仍有未关闭开关时关闭事件的成功次数 = 0。
