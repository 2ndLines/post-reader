## 2. 产品定位与目标

### 2.1 定位
测试台架是只部署在预发环境的内部 Web 工具与命令行工具，承担三件事：

1. **调试**：不经过 iOS 客户端，把一篇帖子跑完整条后端流水线，在每一步查看输入、输出与耗时，并试听每一句合成音频。
2. **评测与对比**：在提示词版本、模型、厂商、音色表之间批量对比质量、延迟与成本，为选型与定价提供数据。
3. **上线门禁**：自动执行主 PRD 第 12 节的全部门禁，以及主 PRD 其他章节中可自动验证、但第 12 节尚未列出的要求（G9–G14，见《业务闭环评审》F13）；配置版本与生产发布只有在所有已启用区域的门禁都通过后才能进行（与《管理后台 PRD》5.8 联动）。

此外，台架负责生成预置样帖包（5.13），保证样帖与线上合成走同一条流水线、满足同样的响度与合成标识要求。

### 2.2 设计原则
1. **门禁必须可信**：每个门禁都配有「必定失败」的反例样本，确保门禁本身没有失效。
2. **结果可复现**：每次运行记录代码版本、配置版本、厂商与模型、样本版本；同样输入重复执行结论一致。
3. **只用安全的数据**：样本只能是合成数据或已确认可用于测试的公开内容。
4. **花费可控**：默认使用回放模式，不产生厂商费用；真实厂商调用有三级预算。
5. **失败有人认领，例外受控**：每个门禁失败都要被认领与分类；放行例外只能通过限时、留痕、不涉及安全合规的豁免。

### 2.3 目标
| 目标 | 衡量方式 |
| :--- | :--- |
| 缩短排障时间 | 开发者定位「某帖播出来不对」的根因不再需要读生产日志或连手机 |
| 发布有依据 | 100% 的配置发布与生产发布都附带两区门禁报告 |
| 选型有数据 | 每次厂商或模型切换前有同样本集上的质量、延迟、成本对比报告 |
| 门禁不漏 | 反例样本在对应门禁上的失败率 = 100% |
| 要求有验收 | 主 PRD 中可自动验证的要求 100% 有对应门禁或明确归属的客户端测试 |

## 3. 用户

| 用户 | 使用方式 | 主要诉求 |
| :--- | :--- | :--- |
| 开发者 | Web 界面 | 调试单帖、对比版本、试听音频、标定音色 |
| AI 编码代理 | 命令行 | 修改代码或提示词后自行运行相关门禁，并读取机器可读的结果 |
| CI 流水线 | 命令行 | PR 检查、部署后冒烟、发布前门禁 |
| 发布负责人（`publisher`） | 在管理后台查看门禁证明，按链接查看报告 | 判断候选版本能否发布 |
| 合规负责人（`compliance`） | 查看国内区门禁报告 | 确认国内机审门禁通过 |
| 产品负责人 | Web 界面 | 查看成本与质量数据，用于配额与定价精算 |
| 运营（`ops`） | Web 界面 | 生成样帖包，下载后在管理后台上传 |

访问需经零信任网关与 Passkey 登录。台架使用预发区独立的账号体系，角色如下：

| 角色 | 权限 |
| :--- | :--- |
| `tb-viewer` | 只读：运行记录、报告、看板（发布负责人、合规负责人、产品负责人默认此角色） |
| `tb-dev` | 发起运行与套件、使用真实厂商（预算内）、认领与分类门禁失败、发起人工评审任务 |
| `tb-reviewer` | 完成分配给自己的人工评审任务 |
| `tb-approver` | 审批门禁豁免、预算上调、样本期望与门禁阈值变更（与仓库的人工审阅一致）；初期由负责人担任 |

| T4 | 新增音色 | 对新音色做响度标定 → 生成音色表变更建议 → 提交仓库 | 5.9 |
| T5 | 发布前门禁 | CI 在两区运行 release 套件 → 报告关联到候选版本 → 管理后台据此放行 | 5.7、5.11 |
| T6 | 线上出现新的注入手法 | 去标识后加入对抗样本 → 确认门禁能拦截 → 若不能则修复后再发布 | 5.8、5.7 |
| T7 | 首段延迟超标 | 端到端模式运行 → 查看时间线找到慢的步骤或厂商调用 | 5.1、5.3 |
| T8 | 配额定价测算 | 用代表性样本集跑真实厂商 → 统计每分钟合成成本与每帖成本 | 5.10 |

## 5. 功能需求

需求编号格式 `TB-<模块>-<序号>`。

### 5.1 单帖运行（RUN）
| 编号 | 需求 | 级别 |
| :--- | :--- | :--- |
| TB-RUN-01 | 输入方式：选择样本库中的样本，或粘贴 `CanonicalPost` JSON。粘贴内容的摘要由台架按清洗与摘要规格自动计算。 | 必须 |
| TB-RUN-02 | 运行参数：区域（国内 / 海外预发）、订阅档位、信息密度、选拔加权、播报风格、目标语言、免译语言、朗读原文 / 译文、提示词版本、厂商组合、音色表版本、厂商模式（回放 / 真实）。 | 必须 |
| TB-RUN-03 | 两种运行模式：**逐步模式**（直接调用流水线各步骤，记录每步输入输出）与**端到端模式**（模拟 iOS 客户端完成登录、签名、创建任务、订阅推送、下载并校验音频、上报播放进度、上报无内容诊断与完整性事件、发起注销与数据导出）。 | 必须 |
| TB-RUN-04 | 运行开始前显示预计花费；超过 $B_{\text{run}}$ 时需确认。 | 必须 |
| TB-RUN-05 | 运行记录保存代码版本、配置版本、样本版本、参数与结果，可一键「以相同参数重跑」。 | 必须 |
| TB-RUN-06 | 逐步模式可指定「止于某步骤」：运行到该步骤为止，之后的步骤不执行、不调用厂商。 | 必须 |
| TB-RUN-07 | **账户场景运行**：按样本中的时间序列注入事件（App Store 服务器通知、发起任务、复听、重复投递、中途配额耗尽、完整性失败上报、运行时开关切换），在每步之后记录账户档位、本期配额与配额流水，与期望比对。App Store 通知使用测试证书签名的模拟通知，不依赖沙盒时序。 | 必须 |

### 5.2 步骤检查（INSP）
| 编号 | 需求 | 级别 |
| :--- | :--- | :--- |
| TB-INSP-01 | 按顺序展示每一步：清洗与摘要、语种判定与分支、评论选拔、翻译与校验（仅跨语种）、串场词生成与溯源、内容机审（国内）、TTS 输入规范化、音色分配、切片合成。每步显示输入、输出、耗时、调用的厂商与模型。 | 必须 |
| TB-INSP-02 | 最终脚本表：播报顺序、发言人角色、音色槽位、情绪、停顿、送入 TTS 的文本摘要，以及它与客户端摘要是否一致（主 PRD 6.1）。 | 必须 |
| TB-INSP-03 | 跨语种条目并排展示原文、译文与校验结论（实体、数值、肯定 / 否定极性、是否新增联系方式），校验未通过的条目标红并说明处理方式（重译或丢弃）。 | 必须 |
| TB-INSP-04 | 串场词展示所用模板与每个槽位引用的原文实体，点击可定位到原文位置。 | 必须 |
| TB-INSP-05 | 音色序列以色带展示，相邻发言人音色相同时标红（主 PRD 8.2）。 | 必须 |

### 5.3 时间线（TL）
| 编号 | 需求 | 级别 |
| :--- | :--- | :--- |

## 8. 安全、数据与成本

1. 台架只部署在两区预发环境，与生产网络隔离，不连接任何生产数据库、缓存或存储。
2. 样本只能是合成数据，或经确认可用于测试的公开内容；禁止导入生产用户内容。线上问题须先去标识，再改写为合成样本。
3. 国内违规测试样本只存放并运行在国内预发环境，海外台架不可见。
4. 预发使用独立的厂商密钥，并在厂商侧设置用量上限；台架自身执行三级预算。
5. 页面与日志不展示厂商密钥；音频产物使用短时签名链接访问。
6. 访问经零信任网关与 Passkey 登录；非开发者角色只读。
7. 用户反馈复现样本按 TB-FIX-06 管理：只含公开内容、无用户身份信息、到期自动删除；不进入门禁样本集。
8. 注销与账户场景只使用台架创建的测试账号，测试账号带统一前缀，不能对非测试账号执行。
9. 门禁证明的签名密钥存放在预发区 KMS，只有台架签发服务可用；公钥随配置包分发给管理后台与发布流水线。
10. 台架的写操作（运行真实厂商、豁免、预算上调、评审任务、失败记录分类）记入台架审计，保留 365 天。
