# 0005 控制通道 WebSocket、音频 HTTPS 切片与跳章协议

- 状态：已批准
- 日期：2026-11-26

## 背景

音频需要逐单元先校验后播放、可缓存复用、可断点续传；服务端需要持续得知播放位置以按需合成；用户需要任意跳章。

## 决策

WebSocket 只传控制消息（脚本单元、章节表、切片就绪、额度、降级；上行位置、跳转、取消）；音频为签名 URL 下载的 AAC 切片。第一版协议即包含 `chapter.map`、`seek`、`seek.ack` 与位置语义的 `progress`；服务端只合成「当前位置 + 30 s」，跳过的单元不合成、不扣点。

## 备选方案与不选的理由

SSE：上行需频繁 POST 与重复签名。WebSocket 或 SSE 推音频字节流：无法先验后播、无法缓存复用，SSE 还需 base64。HLS：播放列表增加延迟，不适合实时生成与逐单元校验。

## 后果（正面、负面、需要跟进的事项）

正面：防篡改、缓存、按需计费、跳章统一。负面：首段依赖小切片设计。
