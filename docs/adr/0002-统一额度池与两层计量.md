# 0002 统一额度池与两层计量

- 状态：已批准
- 日期：2026-11-26

## 背景

产品调用文本生成、翻译、语音合成、神经语音合成等多种模型，各厂商计价口径不同；原方案只按合成音频时长计量。

## 决策

用户侧只有一个额度池（点）。底层按各厂商实际计价口径（输入 / 输出 Token、万字符、语音 Token、音频时长）记录每次调用的原始用量与分渠道成本；用户侧按「区域 × 渠道 × 计价单位」的参数化费率系数实时折算，与原始用量、成本、余额在同一事务中原子核销；主备渠道对同一内容折算差异 ≤ 10%，超过取较低值。

## 备选方案与不选的理由

按音频时长单一计量：无法覆盖文本生成与翻译成本。按真实成本直接扣费：容错切换会让用户多付，且成本波动直接传给用户。

## 后果（正面、负面、需要跟进的事项）

正面：成本可逐条追溯，毛利可按渠道分析，容错不加价。负面：系数需要精算与持续标定。跟进：主 PRD U15、U19、U20。

## 影响的文档与代码
