## 验收标准（助手起草，2026-11-27；负责人确认前视为草案）
1. 音色：
   - 主持人与原帖作者的槽位固定；同一作者全帖不变；`anon:*` 互不相同
   - 首次出场之后的相邻也不同色
   - 300 个随机脚本在槽位够用时相邻同色为 0，回复关系也不同色
   - 槽位不够时仍给出结果，门禁统计会报出相邻同色
   —— 单元测试
2. `select` 校验逐条规则都有拒绝用例：
   - 重复或不存在的 ID、条数越界、情绪缺失或不在枚举中
   - 模板不存在、槽位不是实体、议题标题非空
   - 各密度的条数区间
   —— 单元测试
3. 降级：按点赞数降序、同数保持原顺序，取该密度的上限条数；情绪为 NEUTRAL；无串场；结果本身能通过校验 —— 单元测试
4. TTS 文本：
   - 移除零宽字符；超过 3 个的重复字符折叠为 3 个；转义 `< > &`
   - 按句切分，单句 ≤ 200 个码点，超长的句子在标点或空白处切开，都没有时硬切
   —— 单元测试
5. `pnpm verify`、`knip`、`ci` 工作流全绿

## 计划（助手填写）
- **音色**：在整篇脚本上建冲突图，边来自相邻发言与回复关系。按首次出场顺序贪心着色，避开已着色邻居的槽位。
- **校验结果**：返回问题列表，每项只含 ID 与规则名，不含正文，便于写日志与台架快照。
- **TTS 文本**：先规范化、再切句、最后转义。上限按用户可见的字符（码点）计，不受转义影响。

## 风险与问题（助手填写）
- **Q1 音色约束的范围**：02 §7.4 写的是「按出场顺序」，在首次出场时检查「≠ 上一个发言人、≠ 所回复对象」。这种做法在作者之后再次出场时仍可能与相邻者同色（测试中有反例），而门禁要求为 0。所以改为在整篇脚本上检查冲突，仍按出场顺序贪心。
- **Q2 槽位不够**：每档位至少 4 个槽位，其中评论者可用 2 个。作者多、互相交错时可能无解。无解时复用冲突最少的槽位，门禁会如实报出；是否需要增加槽位，由各档位的音色表决定。
- **Q3 评论少于 `N_min`**：标准密度下，评论总数少于 `N_min` 时全部入选也视为合格。设计没有写明，这是默认做法。
- **Q4 降级的条数**：取该密度的上限（brief 取 `N_brief`，standard 取 `N_max`，deep 取 `N_deep`）。
- **R1 切句**：使用 `Intl.Segmenter`，它的句子边界随 ICU 版本可能略有不同。Node 版本由 mise 锁定，升级时要回归这组测试。
