# P0-CI-01 `ci` 工作流与分支保护

## 目标
每个 PR 和 `main` 推送都跑同一套快速检查，不通过不能合并。

## 依据
- 架构：05 §5.3（GitHub Actions 与 6 条规则）、§2.2（许可证）、§2.5（供应链安全）
- 手册：playbook §2.1、§6.2

## 交付物
- `.github/workflows/ci.yml`：安装（pnpm 缓存）→ Biome → 类型检查 → 单元测试 → gitleaks → 许可证检查 → `pnpm audit`
- 所有 Action 按完整 SHA 固定；顶层 `permissions: contents: read`；`concurrency` 取消同分支旧运行
- 许可证允许清单（05 §2.2）落成配置文件，CI 中检查
- `docs/progress/` 中记录负责人需在 GitHub 上完成的设置清单：`main` 保护（必须 PR、必须 `ci` 通过、必须负责人批准、禁止强推与删除）

## 验收标准
1. 一个只含格式问题的测试 PR 使 `ci` 失败；修复后通过 —— 两次运行链接
2. 一个含假密钥（gitleaks 测试样例）的 PR 被 gitleaks 拦截 —— 运行链接，样例随后删除
3. 工作流中没有未固定 SHA 的 `uses:` —— 脚本检查输出
4. 负责人开启分支保护后，`git push origin main` 被拒绝 —— 输出（出口条件）

## 范围外
`integration`、`contracts`、镜像构建与部署工作流（P1 起各自任务）；Xcode Cloud（P4）；Renovate（单列任务，P0 末或 P1 初）。

## 需负责人
在仓库设置中开启分支保护；确认 Claude GitHub App 或个人凭证的推送方式。

## 计划（助手填写）

- **`.github/workflows/ci.yml`**：一个名为 `ci` 的 job，在 ubuntu-24.04 上运行，步骤依次为：
  1. checkout（完整历史，`persist-credentials: false`）
  2. pnpm/action-setup（读取 `packageManager`）
  3. setup-node（读取 `.nvmrc`，开启 pnpm 缓存）
  4. `pnpm install --frozen-lockfile`
  5. `check:versions`、`check:pins`
  6. `biome ci .`、`typecheck`、`test`
  7. gitleaks（CLI 加 sha256 校验）
  8. `check:licenses`
  9. `pnpm audit --prod --audit-level high`
- **Action 版本**：
  - `actions/checkout` v7.0.1（`3d3c42e…`）
  - `pnpm/action-setup` v6.1.1（`73e4699…`）
  - `actions/setup-node` v7.1.0（`949feb2…`）
  - 三者都是 MIT 许可，发布都已超过 3 天。
- **`tools/ci-checks`**（新 workspace）：
  - 三个纯函数检查：许可证（含 SPDX 表达式求值）、Action 是否按 SHA 固定、工具版本一致性。
  - 每项都有单元测试，覆盖允许、拒绝与边界输入。
  - CLI 由 Node 26 原生的类型剥离直接运行，不引入 `tsx`。
- **`license-policy.json`**：把 05 §2.2 落成配置。允许清单直接放行；MPL-2.0 放行但输出提示；其余许可证只能逐包写入 `exceptions`。
- **文档**：
  - `docs/progress/github-settings.md`：负责人需要完成的 GitHub 设置清单。
  - 05 §5.3、§2.2 回写，文档升到 v1.4。
- **验收方式**：
  - AC1、AC2：以本卡分支为 base 开两个测试 PR。AC1 只含格式问题，修复后再跑一次；AC2 含 gitleaks 官方测试样例。拿到运行链接后关闭 PR 并删除分支。
  - AC3：运行 `pnpm check:pins`，贴输出。
  - AC4：等负责人开启分支保护后再验证。

## 风险与问题（助手填写）

- **R1 不使用 `gitleaks/gitleaks-action`**：该 Action 自 v2 起不再是 MIT，改为限制性许可证，属于 05 §2.2 禁止的「源码可见但限制使用」一类。改为下载官方 CLI 二进制（MIT）并校验 sha256；版本由 `check:versions` 保证与 `.mise.toml` 一致。05 §5.3 已同步修改。
- **R2 自我批准问题（需负责人决定）**：助手用负责人的 `gh` 凭证提 PR，PR 作者就是负责人。GitHub 不允许作者批准自己的 PR，所以一开启「必须批准」，所有 PR 都无法合并。建议给助手单独配置一个机器用户或 GitHub App（详见 `docs/progress/github-settings.md` §1）。在此之前，AC4 无法验证。
- **R3 工作流触发范围**：`pull_request` 不限 base 分支，这样叠在其他分支上的 PR 也会运行 CI；`push` 只针对 `main`。
- **R4 全量历史扫描**：gitleaks 扫描完整历史。如果历史中进入过真实密钥，此后每次 CI 都会失败，直到轮换密钥并按负责人决定处理历史。这是有意为之。AC2 的假密钥只存在于测试分支，删除分支后不会进入 `main` 的历史。
