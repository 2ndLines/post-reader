# P2-SRV-08 厂商 Mock 服务

## 目标
提供 `tools/vendor-mock`：默认按样本回放厂商接口，可注入延迟、错误、挂起与断开连接；录制模式只在负责人授权的任务中运行。本地与 CI 不需要任何真实厂商密钥。

## 依据
- 手册：playbook §6.4（P2-SRV-08 厂商 Mock 服务：录制 / 回放、延迟与错误注入）、§12（厂商接口行为与文档不符时，用 Mock 录制实际响应）
- 架构：05 §3.2 本地服务表（vendor-mock：仓库内 `tools/vendor-mock`，Fastify，端口 4010，默认回放；录制只在负责人授权的任务中、用预发密钥）、05 附录 D、05 §8（厂商 API Key 测试用 vendor-mock）；02 §15 测试层（厂商 Mock：可注入延迟、错误、挂起，用于熔断与切备用测试）
- 红线：AGENTS.md（不记录或外发帖子正文、评论、URL、Cookie、用户 ID 与内容的关联；不调用厂商批处理或文件接口）

## 交付物
- `tools/vendor-mock`：`src/fixtures.ts`（样本格式与加载、匹配）、`src/faults.ts`（故障规则表）、`src/server.ts`（回放、录制、控制接口）、`src/main.ts`（进程入口）、`fixtures/example/echo.json`
- 根脚本 `pnpm mock`；knip 工作区；AGENTS.md 命令表

## 验收标准（助手起草，2026-11-26；负责人确认前视为草案）
1. 回放：按方法、路径与请求体摘要匹配，摘要完全一致的样本优先于不限请求体的样本；没有样本时返回 404 与请求指纹（方法、路径、摘要），不含请求体 —— 单元测试
2. 支持二进制响应（音频等）、首字节时延、流式分块及每块的间隔 —— 单元测试
3. 故障注入经控制接口 `/__mock/faults` 设置，被测代码无感知：状态码（可限定次数，之后恢复）、额外延迟、挂起（客户端超时）、断开连接 —— 单元测试
4. 录制：未显式确认（`VENDOR_MOCK_RECORD_CONFIRM=yes`）时拒绝启动；保存的样本不含请求头、请求体、密钥与 Cookie；录制结果可直接回放 —— 单元测试（本地假上游，不连接真实厂商）
5. 样本文件格式错误时报错并给出文件名 —— 单元测试
6. `pnpm verify`、`knip`、许可证检查与 `ci` 工作流全绿

## 范围外
- 各厂商（LLM、TTS、ASR、审核、Apple）的真实样本：厂商尚未选定，接口格式未知；选定并获得预发密钥后，由各适配器任务卡在负责人授权下录制（P3 起）。
- 熔断与切换备用厂商的逻辑本身（P3 的厂商适配器任务）。
- WebSocket 形式的厂商接口（如某些流式 TTS / ASR）：等选定的厂商确有需要时再加。

## 计划（助手填写）
- **样本格式**：一个 JSON 文件一条：`name`、`vendor`、`request {method, path, bodySha256?}`、`response {status, headers?, body? | bodyBase64? | chunks?}`、`latencyMs?`。请求只存请求体摘要，不存请求体本身（避免把帖子内容写进样本）。匹配不看查询串：录制时查询串照常转发，但不写进样本（有的厂商把密钥放在查询串里）。
- **故障注入**：经控制接口而不是请求头设置。被测代码发出的请求与生产完全一致，故障由测试从外部安排。
- **录制**：转发到 `UPSTREAM_URL`；去掉逐跳请求头；保存时去掉 `set-cookie`、`authorization`、`x-api-key`、`content-encoding`（fetch 已解压正文）等响应头；不保存请求头。
- **请求记录**：`/__mock/requests` 只给方法、路径与摘要，供测试断言调用次数与顺序。
- **新依赖**：无（只用已有的 fastify 5.12.8）。

## 风险与问题（助手填写）
- **Q1 是否进 compose**：05 附录 D 把 vendor-mock 放进 compose。在容器里构建需要 Node 镜像（另需固定 digest）和工作区依赖的安装方式；它只依赖 fastify，在宿主机运行更简单。默认做法：不进 compose，用 `pnpm mock` 在宿主机运行；服务端测试在进程内启动。负责人若要求进 compose，再加 Dockerfile 与镜像 digest。
- **Q2 目录位置**：02 §15 写 `src/test/vendors/`，05 写 `tools/vendor-mock`。默认按 05；02 §15 待负责人确认后同步改为引用 `tools/vendor-mock`。
- **R1 录制的数据**：真实响应的正文可能包含帖子内容的译文或摘要。录制只能用公开或合成的输入（与 playbook §7.5 对站点 fixture 的要求相同：公开内容或合成），提交前人工检查样本；本卡的测试只用本地假上游。
- **R2 回放的 404 会回显路径**：路径来自被测代码自己的请求，只在本地与 CI 出现，且服务不写日志（`logger: false`）。
